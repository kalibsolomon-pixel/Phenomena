## Detection changes and accuracy

The old tracker had only Minemen/PVPHQ adapters. MCPvP, CatPvP, FishFFA and PvPLegacy therefore started at combat and lost normal ends/results. MCPvP's start and FishFFA's second loss require packet surfaces. Minemen #3 restarted from an attack after its result. PVPHQ #2 finalized from a kill when another attack flushed the pending result, then reopened a tiny duplicate for the winner block. A lobby hit before PVPHQ #2 produced another unrelated recording. Inactivity, death and per-round finalization were architecture risks addressed by explicit policies, even where this particular session did not exercise every risk.

Definitions: a timely start/end is within two seconds of the observed signal (logs have second precision). A baseline end recall counts any aligned timely finalization; a stricter whole-match end correctness additionally requires exactly one recording. The primary baseline result is the earliest aligned recording, not a cherry-picked later fragment.

## Performance and limits

The [captured benchmark output](performance/0.1.5/capture.json) records one discarded warmup plus three runs. Host-policy lookup costs 20.9–22.0 ns/op; mixed rule matching 1.10–1.23 μs/op; empty whole-match start/tick/result lifecycle 19.3–30.9 μs/match. Opt-in candidate diagnostics cost 2.51–2.82 μs/op versus 5.9–13.7 ns disabled; queued serialization is outside that synchronous timing.

A 250-round, 5,000-event synthetic match retained one recording through 15,501 simulated seconds (4 h 18 m 21 s), with roughly 7.08 μs/event including boundary parsing/ticks/finalization; offline export took 242 ms for a 3.04 MB HTML file. This advances simulated time; it is not a four-hour wall-clock soak or live FPS measurement. Historical analytics/export totals were 223 ms/3,026 ms across 243 files in the recorded run. Exports and diagnostics serialize on the bounded storage worker; client-thread immutable snapshot copies and final analytics retain their documented costs. Existing automatic event/storage caps remain, and manual memory is not unlimited.

Missing starts/ends, unobserved modes, ambiguous same-opponent rematches after missing ends, absent final-round results, the CatPvP round-count conflict, browser interaction QA and new live six-server acceptance remain explicit review limits. Local development jar: `build/libs/kwamster-0.1.5.jar`.
