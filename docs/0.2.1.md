## What changed

**Report header (new).** Result first as a labelled badge (Win / Loss / Interrupted / Result unknown, with "inferred" stated in words), then the resolution label and source, the title, and a metadata grid: opponent (or participant count), server (or "Hidden (anonymized)" / "Not recorded" — never invented), local date and time with time zone, duration plus combat-active time, recording status (Complete / Interrupted — cause / Manual session / Historical recording) and evidence confidence and scope. Older schemas add plain data-coverage notes ("shown as —, not zero"). Report format, schema, privacy and event count moved to the footer.

**Navigation.** Sticky underline tabs (keyboard arrows/Home/End and hash routing preserved), a skip link, per-tab section chips with a current-section indicator, a manual-session scope bar (participant and exchange filters unchanged in behaviour). Switching tabs while scrolled returns to the top of the new tab.

**Summary and cards.** Six restrained summary cards (accuracy, correlated hits, attributed incoming hits, reach in window, longest combo, advantage share). Every defined metric prints its confidence in words (confirmed / observed / inferred / estimated are styled differently but never by colour alone) and opens its definition inline with a `?` button — previously the definition was a hover-only `title`. Card rows align across a grid row (CSS subgrid). Secondary counts (input breakdown, shield secondaries, jump categories, dominance details) became compact key–value lists instead of more cards.

**Detail without clutter.** Methodology paragraphs are `<details>` blocks ("How this is measured"); long lists (match evidence, incoming hits, shield events, per-hit jump timing, aim grade breakdowns, announcement timeline) are collapsible with their row counts; warnings and unavailable-data notes stay visible. Tables scroll inside their own frame, keep natural column widths on phones and highlight the establishing evidence row.

**Charts.** Same chart set and interactions (combo timeline with selectable bands and Previous/Next, dominance with crosshair, reach histogram with weapon filter, timing scatter with weapon/result filters, jump/incoming tick timeline with zoom sliders, hitbox aim view with weapon/segment filters, shield timeline, exchange strip). They are now laid out at the panel's measured pixel width instead of a fixed 900-unit box, so labels keep 11–13 px on phones; a material width change rebuilds the visible tab and restores its control values. Time axes use 1-2-5 steps and m:ss beyond a minute. Labels are placed greedily and skipped on collision (values remain in tooltips, selects and tables). Tooltips work with mouse, touch and keyboard focus. Colours are the Theme tokens.

**Timeline.** New round and exchange lanes on the event track and a "Go to" selector for any round or exchange. Playback, Prev/Next, speed, seek, click-to-seek, event filter, annotation, live counters and the Space / comma / period shortcuts are preserved. Updates now binary-search sorted event times and only rebuild the event table when the playhead crosses an event, instead of rescanning the whole recording on every animation frame.

**Removed (subtraction pass).** The empty "Result" heading, the duplicate result card group (now the header), the badge row, the monospace/game-font stack (system sans-serif with tabular numerals), per-cell listeners on the 1,200-cell aim grid (one delegated listener), the repeated "Result evidence" key-value row and the manual-session note that repeated header facts.

## Preserved

All payload fields, all 39 metric definitions and their calculations (computed in Java, unchanged), escaping (`scriptSafe`, `textContent`-only DOM writes), CSP (`default-src 'none'`, inline script/style only, `connect-src 'none'`), anonymization, motion omission, reduced-motion flag, every tab, filter, selector and keyboard path of the previous viewer, and missing values rendered as "—" (never zero). ## Performance

Same machine, same headless browser, identical payloads.

| Measure | 0.2.0 viewer | 0.2.1 viewer |
| --- | --- | --- |
| Template size (added to every report) | 73.3 KB | 98.0 KB (+24.7 KB) |
| Exported size, 3-event fight / 880-event match | 91.6 KB / 1,172 KB | 117.0 KB / 1,198 KB |
| Load to `load` event, synthetic set (max per report) | 12–50 ms | 16–49 ms |
| Load, real 10,000-event recordings, Timeline tab | 60–70 ms | 71–85 ms |
| Tab switch incl. first build, synthetic (max) | 2–5 ms | 4–13 ms |
| Tab switch, real 10,000-event recordings (max) | — | 18–26 ms |
| 200 timeline seeks, 10,000-event schema 1 / schema 2 / 5,466-event schema 4 / 880-event synthetic | 930 / 1,065 / 1,006 / 721 ms | 933 / 968 / 885 / 592 ms |
| Max DOM elements (880-event match) | 4,431 | 4,473 |

Interpretation: load and tab switches stay well under 100 ms; tab builds cost a few milliseconds more because charts are laid out at measured widths and carry more labels. Seeking ranges from 0.3 % slower to 18 % faster (≈4.4–4.8 ms per update on 10,000 events); the remaining cost is rebuilding the 200-row event table, which already stays within one frame. The aim grid uses one listener instead of 1,200 per-cell pairs. No animation loop runs while idle (playback uses `requestAnimationFrame` only while playing); transitions are 120 ms colour changes and are disabled under reduced motion. Single runs on a desktop; timings are indicative, not benchmarks.

## Remaining limitations

- Validated in one engine (Chromium/Edge 156). Firefox and Safari were not available on this machine; the page uses only widely supported features (CSS grid/subgrid with a flex fallback, `details`, `IntersectionObserver` guarded, SVG), but they are not verified here.
- Touch input was emulated (mobile viewport metrics and pointer events), not exercised on a physical phone.
- Resizing past a breakpoint rebuilds the visible tab: control values are restored, a selected combo detail or aim-dot selection is not.
- The report remains dark-only, matching the native GUI; a basic print style is included but print output was not reviewed.
- Existing exports keep the 0.2.0 (or KWAMSTER) design until the owner re-exports a fight from History; no bulk regeneration was performed.
