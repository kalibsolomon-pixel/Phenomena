## Manual recording

`/kwm start` and `/kwm end` are Fabric **client commands**, available without server permissions. The client command tree has no server-send operation. The integration test sends the commands through the normal client connection method and probes the integrated server's command handler; none reaches that handler.

Start accepts a connected world with no opponent and rejects duplicate starts. End finalizes once, automatically queues both JSON and offline HTML, and reports save/export progress in local chat. Ending while idle only displays help. Explicit manual recording works even if automatic tracking or automatic saving is disabled in Settings. It does not fabricate a session winner. Intentionally ending an empty manual session saves that requested session once; repeating End produces no duplicate.

The parent session remains active across combat inactivity, automatic starts/results, local deaths and opponent changes. Its children are ordinary measurement exchanges, with their own opponents, evidence, results, shield/aim/reach/timing/jump data, combos and dominance. Known participants retain separate IDs and labels. Unattributed/environmental and third-party damage retain their original attribution. Fast switches can leave delayed source evidence outside an exchange's correlation window; raw session observations remain available without turning them into confirmed hits.

## Recording state machine

| Current state | Input | Transition / preservation policy |
| --- | --- | --- |
| Idle | Combat/server start | Automatic active; existing 0.1.3 lifecycle |
| Idle | Manual Start | Manual active; checkpoint immediately |
| Automatic active | Manual Start | Promote into one parent session, including the existing fight's event prefix; continue that exchange without duplicating hits or emitting a competing top-level fight |
| Manual active | Automatic start/result/inactivity | Parent remains manual; measurement engine may finalize a nested exchange |
| Manual active | Manual Start | No transition; concise already-active message |
| Manual active | End | Finalizing; flush current exchange, checkpoint final parent, enqueue durable recording/HTML exactly once |
| Manual active | Disconnect, world/server change, stop/reset | Finalizing with Interrupted termination; never silently resume elsewhere |
| Finalizing | Snapshot queued | Pending export; ordinary automatic detection is available again |
| Pending export | HTML/receipt available | Idle (unless another automatic/manual session has started) |
| Idle/automatic/pending export | Manual End | No new recording; informative message |

The controller is shared by commands and GUI. Parent duration includes the promoted automatic prefix. `SessionInfo.manualStartEpochMillis` and `manualStartTick` separately preserve the explicit Start request; `startTick`/record timestamps cover the full retained timeline. Automatic match context is cleared after manual finalization, so a later match starts normally. Round-scoped results remain individual results, never a parent-session victory.

## Durability and privacy

Schema 4 adds optional `SessionInfo`; schemas 1–3 still load read-only. Config schema stays 2, with `diagnosticCapture=false`. Reports use format 5. Local manual folders are `Manual Session YYYY-MM-DD HH-MM-SS`; ordinary duel folders retain known opponent names independently of export anonymization. UUID ownership resolves timestamp collisions. Anonymous reports assign distinct Participant aliases rather than merging all opponents.

Every five seconds an immutable session snapshot, including any active exchange, is queued to `kwamster/pending-sessions/<uuid>.json`. Atomic sibling replacement and file flush preserve the previous valid checkpoint if a write fails. Normal End/disconnect/stop queues a final checkpoint before the export job. Startup recovers checkpoints as interrupted sessions, saves/exports them under the same session UUID, and never resumes recording. A final End snapshot retains its explicit termination. An existing finalized recording wins over an older checkpoint, preventing duplicate exports. Corrupt evidence is preserved and reported. Checkpoints remain local; no originals are deleted.

An abrupt process/OS crash can lose observations since the last successfully written checkpoint (normally up to five seconds, longer under disk/queue pressure). Storage failures are reported and the existing automatic pipeline retries exports. There is no inactivity or duration timeout for the parent, but finite resource limits still apply: retained parent data is memory-resident; decoder limit is 1,000,000 parent events and 512 MiB per recording, export digest limit 2 GiB. Child measurement scopes retain the existing 10,000-event limit. Very long sessions increase checkpoint/report cost and memory; unlimited-duration stress acceptance is not claimed.

## Interface and reports

The K key and six-tab design are preserved; no persistent HUD is added. Overview's small Recording section shows live mode, duration, opponent, server, export status and last saved session. Start/End and folder buttons use the same controller as commands. Settings exposes diagnostic capture. History identifies manual sessions, and Fight Flow directs users to per-exchange analysis.

The offline viewer shows a manual-session overview, participants, exchange results/durations and an announcement/round timeline. Participant and exchange selectors switch the existing five report tabs to an independent exchange payload. Session-wide dominance and combo timelines explicitly show unavailable; unrelated opponents are never combined into one dominance curve. Scoped reports retain the existing analytics and safe JSON/HTML escaping, restrictive CSP and absence of network code. Switching scope aborts old playback/keyboard handlers.

## Server rules and diagnostics

Minemen/PVPHQ observed grammars and confidence handling are preserved. The adapter inventory now records rule versions, aliases, capabilities, evidence levels and limitations. Host matching handles case, ports, subdomains and a trailing DNS dot without accepting suffix lookalikes. Cross-server results are rejected. No speculative new-server grammar was added. See [server inventory and evidence workflow](SERVER_COMPATIBILITY.md) for commands, observable surfaces, privacy and fixture preparation.
